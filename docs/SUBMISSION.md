## 2. Draft explanation (edit before submitting)

> **The problem.** [Describe the specific recurring moment in your own work: e.g. the ten minutes at the start of every focus block spent opening the board, starting a timer, silencing the phone and dimming the lamp, then losing the thread of what you meant to do. Or the moment you want a coding agent to take a task without handing it your whole machine.]
>
> **Who it is for.** [Yourself, and people with the same shape of work: developers and researchers who context-switch all day and already dictate rather than type.]
>
> **What it does.** One dictated or typed sentence becomes a bounded plan that you read and approve once. Then it runs, once, and writes a receipt per action: `verified`, `returned`, `sent`, `unknown`, `not_configured`, `desktop_only` or `failed`. It can run a fixed set of routines, call any MCP tool you connect, hand a task to your own coding agent (Claude Code, Codex, Antigravity, OpenCode, Gemini CLI, Aider) in a project folder you registered, and run read-only councils where several agents debate or score a project. Anything unregistered is refused before a plan exists. Approval by voice is off by default and never works for a plan that can delete or destroy.
>
> **How Wispr Flow was used in the build.** [Say what you actually did, with real examples: which requirements you dictated into which tool, which follow-ups you spoke, what broke and how you dictated the fix. Keep it specific and short, and make it match your Insights card.] The product side is deliberately plain: the command box and the dock's capture field are ordinary text fields, so dictation lands at the caret. FlowMesh contains no speech engine.
>
> **What is real, and what is not.** [Keep this paragraph. It is the honest part.] The plan engine, the approval gate, single-use plans, the run record and its hash, the refusals and the HTTP/security contract are covered by automated tests (the Proof page has today's counts) and by CI on Windows, macOS and Linux. The default planner is local rules; a language model is optional and was not run. No real coding-agent answer has yet come through the app, no MCP server was run against a real service, and no real Wispr key press has been recorded into the voice harness. The Proof page lists these under "Still being measured".

## 3. What is verified by engineering (do not claim beyond this)

Live numbers: the **Proof** page (`#/about` in the app) and `web/proof.json`, rebuilt with `python scripts/build_proof.py` from real test runs, the eval, git, the release and CI.

- Both test suites pass (Python and Node) and CI is green on Windows, macOS and Linux.
- Python and the browser planner produce byte-identical plans for every fixture; stored plans reproduce exactly; destructive commands are refused; adversarial HTTP requests get the specified status codes (see [EVAL.md](EVAL.md)).
- Plans are single-use and server-owned (a replay is `409`), run records are written with a SHA-256, the client cannot name an action, path or program, and agent runs only start in registered folders.
- The Windows build was run for real (headless and with its window) and the check found three bugs that tests had missed, since fixed and re-checked on the new exe ([VERIFICATION.md](VERIFICATION.md)).
- The Wispr history reader was checked against the real local Wispr database on the build machine.

## 4. What is explicitly NOT verified (say so if asked)

- A coding-agent task that edits files with a real model, and any real answer from a coding agent through FlowMesh (Codex's own Windows sandbox failed on the build machine).
- Relays and councils with real models; MCP servers against real services (Discord, Slack, Notion, Switch are templates).
- A real Wispr key press into the capture field; the wake word hearing a real voice; the Wispr account sign-in after the person approves.
- Windows system-volume keys and real tab capture; the Home Assistant phone/lamp adapters against real hardware; Jev Choice with a live key.
- The default planner is rules, not a model. Plan quality against human judgement is unmeasured (no labelled corpus).
- No time-saved figure is claimed anywhere; there is no measurement to support one.
- The Windows build is unsigned, so SmartScreen and Gatekeeper warn.
