      HOW IT IS BUILT

      Boring where it matters.

      01 / ONE PLANNER, TWO RUNTIMES

      Deterministic plans

      The same rules produce the same plan in Python and in this page. A parity test runs both over shared fixtures, so the browser edition cannot drift from the app.

      tests/test_parity.py ↗

      02 / THE APPROVAL IS THE BOUNDARY

      Server-owned, one use

      The client sends a plan id, never an action list. Plans expire in five minutes, are consumed once, and every API call needs a per-launch token plus the loopback origin.

      docs/SECURITY.md ↗

      03 / PROOF YOU CAN KEEP

      Durable run records

      Each run writes a Markdown record with the exact words, the approved plan, and every receipt — a file with a SHA-256, not a toast notification that disappears.

      docs/ ↗

      LOCAL APP / PRIVATE CONNECTIONS
